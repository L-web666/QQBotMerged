# QQBotMerged —— QQ 官方机器人多开后台

一个 **单进程、单网页后台** 的 QQ 官方机器人管理程序：

- **多开**：同时运行多个 QQ 机器人（每个机器人独立 AppID/密钥、独立 WebSocket 连接），互不串消息；
- **能聊**：AI 自动回复（任意 OpenAI 兼容接口）、关键词回复、上下文记忆、图片识别；
- **能管**：即时通讯式聊天界面、群管理（成员/禁言/群配置）、指令面板、定时任务、统计与日志；
- **能扩**：支持 **AstrBot 官方格式插件**，且可以给每个机器人启用不同的插件；
- **能备份**：可选 Cloudflare D1 云同步，换设备/重装可把数据拉回来。

> 网页后台共 **11 个页面**、**52 个 HTTP 接口**，设置页 **17 个分组、111 个配置项**，全部有中文说明。

## 一、功能一览

| 分类 | 能力 |
|---|---|
| 机器人 | 多机器人同时在线（各自独立 WebSocket），逐个启用/停用；同一 AppID 会被去重，避免一条消息回两次 |
| 消息 | 私聊 + 群聊；群聊支持「需要 @ 才回复」或「群里所有消息都参与」，全量模式下也能正确识别 @ |
| AI | 任意 OpenAI 兼容接口（DeepSeek / OpenAI / 通义 / Ollama…）、多模态看图、**每个机器人独立的人设与模型** |
| 记忆 | 上下文按「机器人 + 会话」隔离，可设条数；`/清空上下文` 随时重置 |
| 回复链路 | 过滤 → 敏感词 → 内置指令 → 关键词 → 插件 → 限速 → AI，每一步「为什么跳过」都写进日志 |
| 网页聊天 | 即时通讯式界面、未读计数、实时推送（SSE）+ 轮询兜底、点击消息弹操作框、引用回复 |
| 发送 | 文本（纯文本 / **Markdown**，可按机器人设默认值、也可在发送框临时切）、**群内 @ 某人**（官方 `qqbot-at-user` 标签）、**指令标签**（`qqbot-cmd-enter` / `qqbot-cmd-input`，用户点击即可发送或填入输入框）、图片链接、本地上传图片/表情包/GIF、任意文件（大文件自动走官方分片上传） |
| 媒体留存 | 收到的图片/表情包/文件**自动下载留存**（QQ 链接会过期），入库去重，网页引用本地副本 |
| 群管理 | 群列表（按机器人隔离）、群成员、本地禁言 + 官方禁言接口、群级配置覆盖、群名自动刷新 |
| 指令面板 | 按机器人向 QQ 注册可点指令列表（每个机器人独立 panel_id） |
| 定时任务 | 按机器人配置定时发送（北京时间 HH:MM） |
| 插件 | **只支持 AstrBot 官方插件格式**（`astrbot.api.*` 兼容层，可直接放 AstrBot 插件）；支持**按机器人**启用不同插件 |
| 运维 | 运行状态、统计（今日/7 天/累计）、日志查看与下载、上下文文件管理、媒体留存管理、网页端一键关闭程序 |
| 云同步 | Cloudflare D1：上下文 / 插件数据 / 统计等按清单双向同步，冲突取时间戳新者，删除走墓碑 |
| 安全 | 网页访问令牌、管理员 openid、密钥掩码显示、图片代理 SSRF 白名单、插件源码静态安全扫描 |

## 二、环境要求

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows / Linux / macOS 均可（路径全部相对程序目录，无硬编码绝对路径） |
| Python | 3.8+（本项目在 Python 3.14 上开发与测试，更低版本未逐一验证） |
| 依赖 | `flask`、`requests`、`websocket-client`（见 `requirements.txt`） |
| 网络 | 需要能访问 QQ 开放平台接口；图片/文件收发需要能访问 QQ 的多媒体域名 |
| 前置条件 | 一个已创建好的 **QQ 机器人**（在 [QQ 开放平台](https://q.qq.com/) 创建，拿到 **AppID / AppSecret**，并按需开通所需权限） |

> 提示：群聊里想接收「所有人发的消息」需要在 QQ 后台申请对应权限；只申请到「群内 @ 机器人」时，
> 机器人只能看到 @ 它的消息，这是平台限制，不是程序问题。

## 三、安装与启动

### 1. 安装依赖

```bash
pip install -r requirements.txt
```

### 2. 启动

```bash
python run.py
```

启动后打开 <http://127.0.0.1:8666/> 即可。

Windows 也可以双击 **`start.bat`**（会检查依赖，并在程序退出后 3 秒自动重启；不想自动重启就把文件末尾的
`:loop` / `goto loop` 删掉）。Linux/macOS 用 `./start.sh`。

### 3. 首次配置

1. **「设置 → 机器人账号」**：填 **AppID / AppSecret**，勾选「启用」（可以加多个机器人，每个都独立连接）；
2. **「设置 → AI 服务」**：填 API Key / 接口地址 / 模型（任意 OpenAI 兼容服务；留空也能跑，交给插件和关键词回复）；
3. 保存 —— 页面会明确区分「保存即生效」和「需重启生效」；
4. 用 QQ 私聊机器人，或在群里 @ 它，消息就会出现在「聊天窗口」。

### 4. 其他命令

```bash
python run.py --check              # 装配自检（不连 QQ、不开端口）
python run.py --no-bots            # 只开网页后台，不连接 QQ（调界面用）
python run.py --port 9000          # 临时换端口
python run.py --host 127.0.0.1     # 临时换监听地址
python run.py --config my.json     # 使用指定的配置文件
python tests/simulate_message.py --type group --text "你好"    # 往运行中的程序注入一条模拟消息
```

## 五、配置说明

- 配置都在 **`config.json`**（首次运行自动生成，缺失项会自动补全），最方便的改法是网页「设置」页；
  每个配置项的中文名称/说明/单位/范围见自动生成的 `config配置说明文件.txt`。
- **分组作用域**：`AI / 回复 / 过滤与安全 / 功能开关 / 发送策略 / 定时任务 / 指令面板 / 上下文 / 插件`
  属于「**每个机器人自己的设置**」，保存时写进该机器人的覆盖（`bots[].overrides`）；
  其余（网页后台、存储、日志、界面、云同步、权限告警）是**全局**的。
- **环境变量覆盖**（优先级最高，适合服务器/Docker）：

  ```bash
  QQBOT_WEB_PORT=9000                  # → web.port
  QQBOT_AI_API_KEY=sk-xxx              # → ai.api_key
  QQBOT_WEB_TOKEN=my-secret            # → web.token
  QQBOT_CLOUD_SYNC_ENABLED=1           # → cloud_sync.enabled
  QQBOT_AI__API_KEY=sk-xxx             # 双下划线写法也行
  ```

  认不出来的名字会打一条 warning（不会静默忽略）。
- **需要重启才生效**：`web.host / web.port / web.debug`、机器人账号列表、存储相关、重连间隔；
  其余项保存后 2 秒内热更新（日志会写明「改动：xxx；已即时生效」）。
- **安全**：默认只监听 `127.0.0.1`。要改成 `0.0.0.0`（局域网/公网可访问）**务必**先在
  「设置 → 网页后台 → 访问令牌」里设一个令牌，否则任何能访问该端口的人都能操作后台。

### 5.1 消息格式：纯文本 / Markdown

「设置 → 发送策略 → **消息格式**」（配置项 `send.message_format`，默认 **纯文本**）决定消息用哪种格式发出去：

- **① 每个机器人一个默认值**：设置页左上角先选好机器人，再到「发送策略 → 消息格式」里选「纯文本」或
  「Markdown」。它只作用于**当前选中的机器人**（想一次改多个，用设置页右上角的「一键应用」复制过去）。
- **② 本次发送临时切换**：聊天窗口发送框旁的 **`🅼 格式`** 下拉。它**只影响这一次发送**、不写进配置；
  选择结果记在浏览器本地（键 `qbm-send-format`），刷新页面后仍是上次选的。
- **③ 自动发出的消息**：AI 回复、插件回复、定时任务等不经过下拉框，一律**跟随该机器人的默认值**。
  另外在 `Markdown` 模式下，AI 回复不会再被「去掉 Markdown 符号」处理（否则标题/加粗会先被剥掉）。

**官方事实**（依据 QQ 开放平台文档）：

- **无需申请**：2026/04/23 起，单聊与群聊的自定义 Markdown 已对所有机器人开放，**不用申请模板**
  （频道场景仍需内邀开通，本程序不涉及）。
- 发送用的是 `msg_type=2` + `markdown.content`（顶层字段名是 `markdown`，此时不能再传 `content`）。
  这是程序内部行为，不需要你手动拼；对照官方文档或抓包排查时知道即可。
- **官方支持清单**（官方「支持格式」章节逐项列出的语法）：

| 语法 | 写法 |
|---|---|
| 标题 | `# 一级标题`、`## 二级标题` |
| 加粗 | `**加粗**`、`__下划线加粗__` |
| 斜体 | `_斜体_`、`*斜体*` |
| 加粗斜体 | `***加粗斜体***` |
| 删除线 | `~~删除线~~` |
| 有序 / 无序列表 | `1. 第一项` / `- 第一项` |
| 列表嵌套 | 二级列表前空 **4 个空格** |
| 引用 | `> 引用内容` |
| 分割线 | `***` |
| 链接 | `[文字](https://example.com)`、`<https://example.com>` |
| 图片 | `![](https://example.com/a.png)` |
| 换行 | 正文里直接写 `\n` |

- **不在官方支持清单里的语法**（官方没有列出，不保证渲染）：代码块、行内代码、表格、颜色/字号，
  以及 Markdown 的转义规则。写了可能**原样显示**（连 `*` 号一起显示），也可能被平台判为内容不合法。
- **图片**必须是**公网可访问**的 URL（平台会去下载并转存）。本程序留存的图片是本地 `/media/...` 地址，
  **不会**自动转成公网链接；要发图请用图床等公网地址。
- **长度**：官方没有公布 Markdown 的字数上限，超了平台会报错 `40054007`。程序仍按
  「发送策略 → 发送文本上限」（`send.message_max_length`，默认 4000）在发送前先拦一道。
- **失败自动回退**：Markdown 被平台拒绝时（参数错误、长度超限、无权限等 Markdown 相关错误码），
  程序会**自动改用纯文本重发一次**，并把原因写进日志与页面提示（`已回退为纯文本（原因：…）`），
  不会静默失败，也不会把消息丢掉。
- **适用场景**：群聊、单聊都支持发送 Markdown。官方**流式 Markdown 仅单聊支持**，本程序暂不提供。
- **会自动切到 Markdown 的两种正文**：正文里带 **@某人** 或 **指令标签** 时，即使你选的是「纯文本」，
  程序也会**自动改用 Markdown 发送**（这两类标签只在 markdown 消息里会被渲染）；
  发送成功后状态栏会写明原因，例如 `已自动改用 Markdown 发送（检测到 @某人…）`。

### 5.2 群聊 @ 某人（官方 @ 标签）

群里 @ 某人用的是官方标签，写法是 `<qqbot-at-user id="对方openid" />`，客户端会把它渲染成 `@某人`
标签（旧协议 `<@userid>` 官方已宣布即将弃用）。

> **实测提醒**：官方文档写这个标签在文本消息、markdown 消息里都能用，但实测**只有 Markdown 消息**
> 会被渲染，纯文本发出去就是一串尖括号。所以正文里出现 @ 时，程序会**自动把发送格式切成 Markdown**
> （发送框的 `🅼 格式` 会跟着变，状态栏会提示；你也可以手动切回去，发送时后端仍会自动兜底）。

**怎么用（网页）**：在群里打开会话 → 发送框上方点 **`＠ 提及`** 下拉 → 选一个成员 →
标签会**插到光标处**，旁边会显示「将 @：张三」，发送格式同时自动变成 Markdown。
之后照常输入文字、点发送即可（标签可以放在任意位置，也可以一次 @ 多个人）。

- **候选名单从哪来**：官方「查询群成员」接口**要求机器人是群管理员**，所以下拉里除了群成员缓存，
  还会自动补上「**最近在这个群里说过话的人**」—— 普通群也能 @ 到人。名字优先用群成员昵称，
  其次是你在聊天页起的别名。
- **只有群聊支持**：官方写明 @ 仅「群聊、文字子频道」可用。私聊里选择器会被禁用；
  如果你手动把标签粘贴到私聊消息里，程序**不会替你删掉**（它会当普通文字发出）。
- **@全体成员**：官方标注 `<qqbot-at-everyone />` **仅文字子频道可用**、且需要机器人有对应权限，
  群聊里发真标签不生效 —— 所以本程序不提供群里 @全体成员；你在正文里写的 `@全体成员`、
  `<@all>` 会作为**普通文字**发出去（纯文字不会触发格式自动切换）。
- **旧写法照样能用**：正文里写 `<@openid>` 或 `<@!openid>`（定时任务、插件里也常用这种写法），
  发送时程序会自动换成官方新标签，不需要你自己改。
- **收到的 @**：别人 @ 机器人时，聊天窗口会显示成可读的 `@昵称` / `@全体成员` 标签。

### 5.3 指令标签（`/回车指令`、`/参数指令`，仅 Markdown）

官方「指令操作」支持两种**可点击标签**，用户点一下就能省去手动打字。**只有 markdown 消息支持**，
所以插入时程序会自动把发送格式切成 Markdown。

| 标签 | 官方写法 | 用户点击后 |
|---|---|---|
| 回车指令 | `<qqbot-cmd-enter text="xxx" />` | **直接发送** `text`（点击即发出，用户不用再点发送） |
| 参数指令 | `<qqbot-cmd-input text="xxx" show="xxx" reference="false" />` | 把 `text` **插入输入框**，用户自己改完再发 |

**怎么用（网页）**：发送框上方点 **`⌘ 指令`** → 选「回车指令 / 参数指令」→ 填**文本**
（例如 `/帮助`）→ 参数指令还可以填**显示文本**、勾选**带引用回复** → 点「插入」。
标签会插到光标处，同时自动切到 Markdown，旁边显示「已插入 N 个指令标签」。

- **`text` / `show` 最长 100 字符**（官方限制），程序在插入前就会拦下来；两个值都会**自动 urlencode**
  （官方要求：`/`、中文、`&`、空格都会被编码），你只管写人话。
- **`show` 是"用户看到的文字"**：不填时官方默认取 `text`，程序也不会重复写这一段。
- **`reference="true"`**：参数指令才用得上 —— 用户点击后插入输入框时，会**带上这条消息的引用回复**。
- **群里用不了回车指令**：官方原文写明「群聊和文字子频道不支持该能力」，所以回车指令主要用在单聊；
  参数指令在群聊里正常。程序不做场景判断（官方对回车指令的限制是客户端行为，写错了最多是不生效）。
- **手动写也可以**：直接在正文里写 `<qqbot-cmd-enter text="%2Fhelp" />` 效果一样，
  后端还会自动把格式升级成 Markdown；收到的指令标签在聊天窗口里会显示成绿色的 `/回车指令 …` 标签。

## 六、回复链路与消息规则

处理一条消息的顺序（每一步「为什么跳过」都会写进日志，便于排查）：

```
1 群/私聊总开关 → 2 本地禁言拦截 → 3 敏感词输入拦截 → 4 群聊是否需要 @
→ 5 去掉开头的 @提及 → 6 附件转文本 → 7 无意义消息过滤 → 8 内置指令
→ 9 关键词回复 → 10 插件（AstrBot） → 11 限速 → 12 AI 回复
```

内置指令：`/帮助`、`/清空上下文`、`/群设置`、`/图片说明 <链接>`；管理员另有管理指令。

关于群聊的两个平台行为（容易困惑，先说清楚）：

- **「接收所有消息」（全量模式）**：如果机器人在 QQ 后台开了这个权限，群里**每条消息**都会推给程序，
  此时「有没有 @ 机器人」由程序根据消息里的 mentions 判断；默认**只在自己被 @ 时回复**
  （可在「群管理」里关掉「需要 @ 才回复」，让它参与全部聊天）。@全体成员不算 @ 机器人。
- **@ 标记显示**：程序会把收到的 `<@openid>` / `<@all>` 这类标记在网页里显示成可读的 `@某人` / `@全体成员`。
  网页端**暂不支持发送 @**（QQ 新的 @ 标记格式在群里支持不稳定，等平台稳定后再补）。

## 七、插件系统（AstrBot 官方格式）

**只支持 AstrBot 官方插件格式**，目录约定与官方一致：

| 内容 | 位置 |
|---|---|
| 插件本体 | `plugins/<插件名>/`（必须含 `metadata.yaml` + `main.py`） |
| 插件配置项定义 | `plugins/<插件名>/_conf_schema.json`（可选） |
| 插件配置值 | `data/config/<插件名>_config.json`（自动生成，可手改） |
| 插件数据 / 大文件 | `data/plugin_data/<插件名>/` |
| 插件依赖 | `plugins/<插件名>/requirements.txt`（可选） |

以 `_` 或 `.` 开头的目录、裸 `.py` 文件都会被忽略。最小插件：

```python
from astrbot.api.event import filter, AstrMessageEvent
from astrbot.api.star import Context, Star
from astrbot.api import logger


class MyPlugin(Star):
    def __init__(self, context: Context, config=None):   # 有 _conf_schema.json 时官方会传 config
        super().__init__(context)
        self.config = config or {}

    @filter.command("hello")
    async def hello(self, event: AstrMessageEvent):
        """这是指令说明（会显示在指令面板里）"""
        yield event.plain_result(f"你好，{event.get_sender_name()}！")

    async def terminate(self):
        """插件卸载/停用时调用，可选"""
        pass
```

- 兼容层实现了 `astrbot.api.*` 的常用子集：`Star` / `filter` / 事件 / 消息链 / 配置 /
  KV 存储（`put_kv_data` 等）/ `StarTools` / provider 调用，并模拟 `ASTRBOT_VERSION = 4.9.2`。
- **暂不支持**（插件页会逐个列出，而不是静默失败）：插件自带 Web 接口与 Pages、`register_llm_tool`、
  文转图模板、会话控制器、知识库、Agent 执行器等 AstrBot 专有组件。
- 仓库自带 4 个示例/实用插件：`astrbot_demo`（文字/图片/管理员指令）、`astrbot_plugin_dice`（骰子）、
  `astrbot_plugin_daily_checkin`（签到/积分/抽奖）、`astrbot_plugin_ollama`（本地 Ollama 接管普通消息）。
- **安装**：把插件目录整个复制进 `plugins/` → 「插件管理」页点「丢弃修改并重载」；
  全局启用/停用后点「保存插件设置」生效。

### 7.1 按机器人启用不同的插件

插件默认对**所有机器人**生效，也可以让每个机器人跑不同的插件组合：

- **网页**：「插件管理」页有「**当前机器人**」一列，勾选 = 左上角选中的机器人运行该插件，
  不勾 = 只有其它机器人运行；点一下立刻保存。「保存插件设置」管的是**全局**启停，两者互不影响。
- **设置页**：「设置 → 插件系统」里有 `本机器人启用的插件`（白名单）与 `本机器人停用的插件`
  （黑名单，优先级更高），每行一个插件名，作用于当前选中的机器人。
- **配置文件**：写在该机器人自己的覆盖里，全局段不受影响：

  ```jsonc
  {
    "plugins": { "enabled": true, "dir": "plugins" },   // 全局：插件总开关与目录
    "bots": [
      { "id": "bot1", "name": "主力机器人", "overrides": {
          "plugins": { "enabled_names": [], "disabled_names": ["astrbot_plugin_dice"] }
      }},
      { "id": "bot2", "name": "备用机器人", "overrides": {
          "plugins": { "enabled_names": ["astrbot_plugin_daily_checkin"], "disabled_names": [] }
      }}
    ]
  }
  ```

- 规则：某插件要跑在某机器人上，需要同时满足 —— 全局插件系统开着、插件没被全局停用、
  不在该机器人的黑名单里、且（该机器人白名单为空 **或** 插件在白名单里）。两个名单都为空 = 不限制。
- 隔离范围：消息分发与 `on_llm_request` 等钩子都按机器人过滤；插件代码本身仍是**同一份实例**
  （`data/plugin_data/<插件名>/` 是共享目录），所以「每个机器人独立保存插件数据」需要插件内部
  用 `event.get_self_id()` 之类的字段自行区分。

### 7.2 安全提示（重要）

> ⚠️ **插件是任意 Python 代码，运行在程序主进程里，没有沙箱。**
> 它能读写你机器上的任意文件（包括 `config.json` 里的 AppSecret 与 AI 密钥）、能联网、能起线程/进程。
> **请只放你自己写的、或来源完全可信的插件。**

为了帮你判断，「插件管理」页会对插件源码做**静态扫描**（只解析 AST，不执行代码），
把「这段代码能做什么」标出来（执行命令 / 读写文件 / 联网 / 动态执行 / 读取配置密钥等）：

```bash
python -m core.plugin_safety plugins        # 命令行自查（不启动程序）
```

扫描结果是**提示**，不是沙箱，也不代表插件一定是恶意的 —— 装第三方插件前值得看一眼。

## 八、数据、备份与云同步

`data/` 下都是运行时数据：

| 路径 | 内容 | 说明 |
|---|---|---|
| `messages.db` | 消息 / 会话 / 媒体索引 / 群成员 / 禁言 | SQLite（WAL），**最值得备份的文件** |
| `media/` | 自动留存的图片、表情包、文件 | 可清理；删了网页就看不到历史图片 |
| `logs/` | 运行日志（按大小分割） | 可清理 |
| `user_context/` | AI 上下文 JSON（按机器人 + 会话） | 可清理（删了 AI 就"失忆"） |
| `config/<插件名>_config.json` | 插件配置 | 可能含插件自己的密钥，**不上云** |
| `plugin_data/<插件名>/` | 插件数据 | 参与云同步 |
| `group_settings.json` / `group_names.json` / `stats.json` / `command_panel.json` / `plugins_disabled.json` | 群配置 / 群名 / 统计 / 面板 id / 插件启停 | 参与云同步 |

**备份**：停掉程序后，整个复制 `data/` 与 `config.json` 即可。只备份 `data/messages.db`
也能保住聊天记录（还有 `-wal`/`-shm`，**运行中复制不保险**，建议先关程序）。
换设备时把这两样拷过去，装上依赖启动就行。

**云同步（可选，Cloudflare D1）**：在「设置 → 云同步」填 `account_id / database_id / api_token` 并启用；
「运行状态」页有测试连接 / 立即同步 / 解除暂停。同步范围是上表标了"参与云同步"的那些；
**永不上云**：`config.json`（含密钥）、消息库、留存媒体、日志。
另外，含 `api_key / secret / token / password` 这类**字段名**的文本/JSON 默认也会跳过上传
（可在「设置 → 云同步」关掉这个开关）。同一套 D1 不要在**多台设备同时**开启同步，否则会互相覆盖。

## 九、常见问题

**启动后网页打不开 / 提示"程序已在运行"**
程序有单实例保护（`data/merged.lockdir` + `data/instance.json`）。确认没有别的实例在跑后，
删掉 `data/merged.lockdir`、`data/merged.lock`、`data/merged.pid`、`data/instance.json` 再启动。
端口被占用就换一个：`python run.py --port 9000`，或在设置里改端口。

**机器人在群里不回复**
先看日志，程序会直接写明原因，例如 `群消息未 @ 机器人，已跳过`、`群 … 已关闭自动回复`、
`成员 … 处于禁言状态`。最常见的是：机器人只拿到了「群内 @」权限，但你希望它回复所有消息；
或者反过来，「群内所有消息」权限已开、而「需要 @ 才回复」还开着。

**发文件失败**
QQ 官方限制：文件 200MB、图片 20MB；超过阈值会自动改用官方分片上传。平台对"文件消息"支持有限，
失败时会自动退化为「发送下载链接」并说明原因。

**选了 Markdown 但消息显示成纯文本 / 带 `*` 号**分两种情况：

- **平台把 Markdown 拒了，程序自动回退**：日志里会有一条
  `markdown 发送被平台拒绝，自动回退为纯文本重发：…`，后面跟着平台返回的**错误码**
  （例如 `40034124` markdown 参数错误、`40054007` 消息长度超限）；聊天窗口状态栏也会显示
  `已回退为纯文本（原因：…）`。照错误码调整内容（缩短、去掉不合法的写法）再发即可。
- **语法不在官方支持清单里**：代码块、行内代码、表格、颜色/字号这些官方没列出的语法不会渲染，
  会**原样显示**（所以还能看到 `*`、`#` 之类的符号）。改成上一节列出的写法即可正常渲染。

想直接切回纯文本：把发送框旁的 `🅼 格式` 下拉切到「纯文本」（只影响本次，浏览器会记住选择）；
或者到「设置 → 发送策略 → 消息格式」把当前机器人的默认值改成「纯文本」——AI 回复、插件回复、
定时任务也会一起跟着变回纯文本。

**群里 @ 了人却显示成一段文字 / 没弹出 @ 标签**
按下面顺序排查（官方规则就是这几条）：

- **这条消息必须是 Markdown 发的**：实测 @ 标签只在 markdown 消息里被渲染。程序在正文含 @ 时
  **会自动把格式切成 Markdown**（插入 @ 后看发送框的 `🅼 格式` 是不是 Markdown）；
  如果你手动切回「纯文本」，纯文本发出去就会显示成 `<qqbot-at-user id="…" />` 这段文字。
- **只有群聊支持**：私聊里 @ 标签不生效，会显示成普通文字；网页端在私聊里已经把选择器禁用了。
- **标签要带对方的成员 openid**：正确写法 `<qqbot-at-user id="对方openid" />`。
  用发送框的 `＠ 提及` 下拉选人就不会拼错；手动粘贴时注意别把 openid 写错（写错平台不会报错，只会显示成文字）。
- **@全体成员 在群里不生效**：官方标注它**仅文字子频道可用**，所以本程序把 `@全体成员` / `<@all>`
  当普通文字发出去 —— 这是预期行为，不是 bug。
- **确认机器人是自己发的这条消息**：用别人的号 @ 你是对方客户端的事，程序这边只负责"发出去"。
- 如果下拉里**没有想 @ 的人**：官方群成员接口要求机器人是群管理员；程序会自动补上
  「最近在这个群里说过话的人」，所以让对方先在群里说一句话，再刷新会话即可。

**指令标签（`/回车指令`、`/参数指令`）插了没反应**
先确认这两点，再排查别的：

- **只有 Markdown 消息支持**：插入时程序已经自动切成 Markdown；如果你手动改回纯文本，标签就会
  变成一段尖括号文字。
- **回车指令在群聊里不生效**：官方原文写明「群聊和文字子频道不支持该能力」，群里请用**参数指令**
  （用户点击后文本会插入输入框，再自己点发送）。单聊里两种都正常。
- **`text` / `show` 上限 100 字符**：超了程序会在插入前就拦住并提示；`text` 为空也不会生成半截标签。
- 标签里的值是 **urlencode** 过的（官方要求），所以在 QQ 里看到 `%2F` 之类只是编码，客户端会自动还原；
  手动编辑时别把它解码后再粘回去。

**撤回 / 引用**
自己发的消息 2 分钟内可撤回；撤回**群成员**的消息需要机器人是群管理员；
引用超过 2 分钟的消息用 `message_reference`（程序会自动降级，不会因为过期而整条失败）。

**群成员列表是空的**
官方 `GET /v2/groups/{gid}/members` 目前要求机器人是群管理员（否则返回 11253）。
拉不到时程序会用**历史消息里出现过的成员**补齐，禁言/解禁照样可用。

**@全体成员**
官方文档写明「仅文字子频道可用」，群聊里机器人发 @全体成员基本不生效，因此本程序不提供该发送功能。

**网页安全**
默认只监听 `127.0.0.1`。改成 `0.0.0.0` 时必须设置访问令牌，否则任何能访问该端口的人都能操作后台。
另外程序是 Flask 自带的开发服务器，长期对外使用建议放在反向代理（Nginx/Caddy）后面并配 HTTPS。

**配置文件写坏了 / 程序起不来**
程序会先把你原来的 `config.json` 备份成 `config.json.broken-<时间>`，再用默认配置启动，
日志里会写明怎么恢复 —— 原文件不会被直接覆盖。
